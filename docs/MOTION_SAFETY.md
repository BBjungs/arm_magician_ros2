# Motion and safety

The application builds an in-memory motion transport only in simulation mode. The ROS action goal requires an expiring capability bound to operation, TCP target and speed. The permit is consumed once, and STOP revokes pending permits synchronously. The controller verifies operator lease, fresh joints and TCP, alarm state, an explicit HOME assertion for observation and centering, RGB-D, target depth, workspace and joint bounds, speed, step size and simulated workcell and E-stop flags. HOME has its own initial reference-pose checks through the same guarded path. Every new setup move requires separate web confirmation.

The simulated links have affine endpoint and joint positions. The convex hull of the start and end positions of each link's endpoints contains its continuous swept volume. Expanded axis-aligned bounds cover the link radius and a separate bound covers the tool/camera assembly. The supervisor checks the resulting bounds against table clearance and obstacle boxes. This is conservative for the defined mock geometry. The physical parallelogram, joint interpolation, cables, self-collision, fixtures and stopping distance need a commissioned hardware model.

Each action reports moving, settling or stopping feedback, TCP readback and terminal diagnostics. STOP invalidates authorization and requests transport stop and action cancellation. The controller verifies connection, a stationary reading and a settling window independently of the ROS action result. It compares the measured TCP with the goal before declaring move success. Unverified stop, readback mismatch and unexpected motion latch FAULT. The mock controller restarts unhomed and without a previous lease, target or motion command.

`real_motion_enabled: true` and `autostart_motion: true` are rejected at startup. The hardware driver still implements only GET. Controller firmware compatibility, actual HOME behavior, motion queue semantics, cancellation, force-stop, queue clearing, subsequent readbacks and STOP latency need verification on the installed Magician before implementing a Serial SET transport.
